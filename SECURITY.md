# Security Policy

## Supported Versions

| Version | Supported |
|---|---|
| Latest (`main`) | ✅ |

---

## Reporting a Vulnerability

**Please do NOT open a public GitHub issue for security vulnerabilities.** Doing so exposes all users to risk before a fix is available.

### Option 1 — GitHub Private Vulnerability Reporting (Preferred)

1. Go to the [Security tab](https://github.com/vishnu-593/oss-atlas/security) of this repository.
2. Click **"Report a vulnerability"**.
3. Fill in the advisory form — describe the issue, affected versions, and steps to reproduce.
4. Submit. Only the maintainers can see this report.

### Option 2 — Email

Send details to the maintainers via the contact on their GitHub profiles ([@vishnu-593](https://github.com/vishnu-593) or [@meghana0667](https://github.com/meghana0667)). Use the subject line:

`[oss-atlas] Security Vulnerability Report`

---

## What to Include

- **What** is the vulnerability? (e.g. SQL injection, path traversal, data leakage)
- **Where** in the code? (file, endpoint, line number if possible)
- **How** can it be exploited? (minimal reproduction steps)
- **Impact** — who is affected and under what conditions?
- **Version** — which version/commit is affected?

---

## Disclosure Process

1. You report privately.
2. Maintainers acknowledge within **72 hours**.
3. Maintainers investigate and develop a fix — target **14 days** for critical issues.
4. A patched release is published.
5. A GitHub Security Advisory is published crediting you (unless you prefer to remain anonymous).
